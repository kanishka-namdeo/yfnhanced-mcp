# src/middleware

## Purpose

Reusable resilience primitives — cache, circuit breaker, rate limiter, retry, security gate — each owning one algorithm and its statistics.

## Ownership

- This folder owns the mechanics and their configurable parameters. `src/services/yahoo-finance.ts` owns where they are composed and in what order; `src/utils/security.ts` owns the stateless validation rules that `middleware/security.ts` delegates to.
- No chain abstraction exists. `MiddlewareChain`, `MiddlewareFunction`, and `use()` in `src/types/middleware.ts:236-246` are declared and never implemented; nesting is hand-written in the service.

## Local Contracts

- `Cache` (`cache.ts:223`, re-exporting `LRUCache`, `StaleWhileRevalidate`, `CacheMetrics` at `:450`) takes `CacheConfig` from `src/types/config.ts:21`; `maxEntries` is LRU capacity. TTL is chosen by `getTTLForType` (`:420-427`) prefix-matching `quote`/`historical`/`financial`/`news`/`analysis` against `DEFAULT_TTL` (`:4-10`: 60 s / 1 h / 24 h / 5 m / 1 h) then falling back to `config.ttl`; the match is `startsWith`, so the singular tokens also catch plural key prefixes — `quotes:AAPL` matches `quote` and `financials:X` matches `financial`. A key that matches none of the five gets `config.ttl`, not the type default. Expired entries are deleted and reported as a miss (`:246-250`); `STALE_THRESHOLD` is 0.5 (`:12`); revalidation failure serves the stale value until expiry, otherwise rethrows (`:213-219`); `warm` routes errors to `config.onError` (`:408`). Promise-returning methods without internal awaits (`get`/`set`/`delete`/`clear`/`has`/`getEntry`/`keys`/`touch`/`mget`/`scan`, plus `StaleWhileRevalidate.get`) execute their bodies synchronously — `scan` uses a `new Promise` executor so an invalid regex pattern still rejects instead of throwing — and only resolve the value. Storage is in-memory only — `store: 'memory'` (`src/index.ts:122`) — and the `redis`/`file` config fields are never read.
- `CircuitBreaker` + `CircuitBreakerOpenError` (`circuit-breaker.ts:37`, `:10`). States are uppercase `'CLOSED' | 'OPEN' | 'HALF_OPEN'`, while `src/types/config.ts:69` types a lowercase union — the runtime value wins. Transitions: CLOSED→OPEN when `failureCount >= failureThreshold` after rolling-window cleanup (`:120`, `:152-157`); OPEN→HALF_OPEN lazily on `execute`/`getState` once `now - lastStateChange >= timeoutMs` (`:67`, `:91`); HALF_OPEN→CLOSED at `successCount >= successThreshold` (`:106`); HALF_OPEN→OPEN on any single failure (`:118`); `reset()` forces CLOSED (`:125`). Despite the config names there is no volume threshold and no percentage logic. Constructor accepts `{} as CircuitBreakerConfig`, so defaults are inline (`:53-62`): `failureThreshold` from `errorThresholdPercentage || 5`, `successThreshold` from `halfOpenMaxAttempts || 3`, `timeoutMs` from `resetTimeoutMs || 60000`, `monitoringWindowMs` from `rollingCountTimeoutMs || 60000`. `getConfig()`/`updateConfig()` use the private `CircuitBreakerConfigInternal` (`:26`), and `isClosed`, `isHalfOpen`, `forceOpen`, `forceClose` from `CircuitBreakerInterface` (`src/types/middleware.ts:145`) are not implemented.
- `RateLimiter` (`rate-limiter.ts:265`) is a hybrid: continuous-refill `TokenBucket` (`:43`, `:56`), fixed calendar-window `RateLimitTracker` per minute/hour (`:88-126`), and `AdaptiveThrottling` from response headers (`:159`, `:178`). Defaults: `refillRate = orFallback(tokenRefillRate, 1)` (`:284`, helper at `:6` keeps 0/NaN falling through like `||` did), capacity `= maxRequests`, `burstLimit = 5` (`:298`), `maxConcurrent = maxRequests || 10` (`:300`), adaptive floor `floor(maxRequests * 0.25)` (`:293`). Exhaustion throws `RateLimitError` (`:12`) — it never queues — including predictive throttle above `usageRatio > 0.7` (`:321`, `:443`) and token depletion (`:331`). Only concurrency queues, FIFO through `waitForSlot()` (`:450`) on a 100 ms `setInterval` (`:466-479`) that keeps the event loop alive. A 429 inside `execute` first returns a cached `rate_limited_${key}` value before throwing (`:403-414`).
- `RetryPolicy`, `createRetryPolicy`, `retry`, `MaxRetriesExceededError` (`retry.ts:29`, `:248`, `:252`, `:8`). Retries when `classifyError` marks the error retryable and its status is in `config.retryableStatusCodes` (`:133`), or the code is in `ECONNRESET`/`ETIMEDOUT`/`ENOTFOUND`/`ECONNREFUSED` (`:5`), or the message contains timeout/network/rate limit/cookie/session (`:6`). Backoff is exponential `initialDelayMs * backoffMultiplier^(attempt-1)`, or `linear`/`fixed` (`:157-171`, where a `retryDelayMs` of 0 or NaN falls back to `initialDelayMs`), capped at `maxDelayMs` (`:175`), with ±25% jitter and a 100 ms floor (`:188-195`); per-error multipliers are rate-limit ×2 or `retryAfter * 1000`, cookie ×0.5, 502/503/504 ×1.5 (`:203-227`). Loop bound `attempt <= maxRetries + 1` (`:65`) never reaches its extra iteration: `shouldRetry` returns false as soon as `attempt + 1 > maxRetries` (`:118-121`), so at most `maxRetries + 1` attempts run. `MaxRetriesExceededError` is thrown at `:51` and `:76`. It sets no interaction with the breaker: `CircuitBreakerOpenError` carries `isRetryable = false` (`circuit-breaker.ts:16`) and exits immediately. `MaxRetriesExceededError` is the only place `YF_ERR_MAX_RETRIES_EXCEEDED` is set.
- `SecurityMiddleware` (`security.ts:4`) is the stateful wrapper — `blockedIPs`, `requestCounts`, `suspiciousPatterns`, auto-block after 5 hits (`:121`) — gated by `SecurityConfig` flags, delegating rules to `src/utils/security.ts`; its `validateInput`/`sanitizeOutput`/`checkRateLimit` return Promises via synchronous executors, so validator throws reject and counter mutations stay in-call. It runs on the MCP boundary only, in `src/server.ts` (input, output, error, resource URI). Measured 2026-10-14: only `validateInput`, `sanitizeOutput` and `sanitizeError` are ever called — `block`, `isBlocked`, `checkRateLimit` and `recordSuspiciousActivity` are dead code, so `blockedIPs` can never gain an entry and the whole IP-blocking feature is fiction; `blockDurationMs`, `maxStringLength`, `maxSymbolsPerRequest` and `enableRateLimiting` are read into the class and never consulted; and the `/g` `lastIndex` leak in `src/utils/security.ts` propagates through `validateInput`.
- `RateLimiter.reset()` mid-flight drives the per-endpoint concurrency counter negative (`release()` is unclamped), and `RetryPolicy` with a non-numeric `maxRetries` runs zero attempts and throws a bare `Error` rather than `MaxRetriesExceededError`. Both are pinned by `tests/unit/middleware/` rather than fixed.
