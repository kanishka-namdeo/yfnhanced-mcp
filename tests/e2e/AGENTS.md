# tests/e2e

## Purpose

Drive the built server over its real transport — spawn `dist/index.js`, exchange JSON-RPC on stdio — plus one suite that calls the tool modules in-process against a stubbed `yahoo-finance2` seam.

## Ownership

- `server.e2e.test.ts` startup, handshake, listings, notifications, error framing and process lifecycle; `tool-execution.e2e.test.ts` the 17 registered tools; `resource-access.e2e.test.ts` `resources/*`; `prompt-execution.e2e.test.ts` `prompts/*`; `real-world.test.ts` in-process tool-module behavior with no network.
- Layer-wide rules (commands, coverage, mocking policy) stay in `tests/AGENTS.md`.

## Local Contracts

- `import.meta` is banned in every file here: the Jest transform forces `module: 'commonjs'` (`jest.config.js:15`) and cannot downlevel it, so a file that uses it fails to load with "Must use import to load ES Module". Paths use `__dirname` / `path.resolve(__dirname, '../../dist/index.js')`, which `@types/node` provides under that transform. `server.e2e.test.ts` reads `package.json` with `readFileSync` + `JSON.parse` for the version assertion; there is no `createRequire` here.
- Build guard, all four spawned files: reject with `Server build not found. Run "npm run build" first.` when `dist/index.js` is absent. `npx jest tests/e2e` therefore requires `npm run build` first, and the built entry is `dist/index.js` (thin process entry over `src/server.ts`).
- One child process per file, spawned in `beforeAll`, never per test, and killed in `afterAll`. Readiness is the stderr line `Yahoo Finance MCP Server started successfully` — it is emitted only after `state = 'ready'`, so every list handler is already registered; waiting on that string on stdout would hang forever because diagnostics go to `console.error`. Startup is dominated by the client's warm-up quote and measures 2.4–3.8 s. Shutdown escalates `stdin.end()` (transport EOF, the child exits 0 in ~1.2 s) → `SIGTERM` → `SIGKILL`, because `MCPServer.shutdown()` does not close the transport and the rate limiter's 100 ms `setInterval` keeps the child alive; every spawned child is registered in a file-local list so a hung child cannot leak into the next suite.
- Child env is `NODE_ENV: 'test'` only. `USE_MOCK_API` and `PORT` are gone: nothing in `src/` reads them, the transport is stdio, and the only env variable the loader honors is `YF_MCP_CONFIG_PATH`.
- Requests are correlated by JSON-RPC `id` through one shared stdout line reader installed at spawn. The old per-request `stdout.on('data')` listeners leaked, raced each other, and reset their buffer on a parse error, which lost frames.
- Each file asserts stdout framing continuously: every newline-delimited stdout chunk must parse as one JSON-RPC 2.0 object carrying `id` or `method`, nothing may be left in the buffer at the end, and no unsolicited message may arrive. That is the only way a stray `console.log` in `src/` is caught from this layer (hard `src/AGENTS.md` contract).
- Network-free by design, in the default run: handshake and `serverInfo` (name `y-finance-mcp-server`, version equal to `package.json`), `tools/list` = exactly 17 with `inputSchema.type === 'object'` and every `required` key present in `properties`, `resources/list` = 6, `resources/templates/list` = 6, `prompts/list` = 6, notifications producing no response, unknown method = `-32601`, non-object `arguments` = `-32603`, unknown tool name / missing arguments / empty `symbols` / out-of-grammar symbol = `isError: true` envelope, and every one of the 17 tools proven to have a dispatch entry by a probe its own validation layer rejects before any Yahoo call.
- Live groups are `describe`s named `… — live market data (requires network access to Yahoo Finance)` and are the only tests here that touch the network. They are kept last in each file so the deterministic result is unaffected, and they assert real payload shapes rather than envelope presence, so an upstream outage or 429 degrades them to red instead of green-for-the-wrong-reason. Membership: `server.e2e.test.ts` 2 (a `get_quote AAPL` call, a `ticker://AAPL/quote` read); `tool-execution.e2e.test.ts` 42 (all per-tool data cases for the 17 tools, incl. `get_quote_summary`, which validates nothing and therefore cannot be probed offline); `resource-access.e2e.test.ts` 11 (all `resources/read` cases); `prompt-execution.e2e.test.ts` 0 — prompt rendering is pure string templating in `src/server.ts`, so that whole suite is offline; `real-world.test.ts` 0.
- `real-world.test.ts` stubs the seam the code actually calls: the shared `yahooFinance` singleton exported by `src/services/yahoo-finance.ts`, replacing `quote`, `chart`, `quoteSummary`, `search`, `options` and `fundamentalsTimeSeries` with fixtures, and restoring them in `afterAll`. `YahooFinanceClient`, the middleware stack, the tool handlers, the zod schemas and the data-quality scoring all run for real. Nothing here reaches the network, so it passes offline and needs no build.
- `YahooFinanceClient` in `real-world.test.ts` is constructed with the key names the middleware classes read (`maxRequests`, `errorThresholdPercentage`, `initialDelayMs`, …) exactly as `src/server.ts:132-188` maps them, with `maxRetries: 0`. Handing it `defaultConfig` directly — what this file used to do — leaves every limiter capacity `undefined` and drops the breaker to its inline 5-failure threshold, so one refused symbol opened the circuit for the rest of the suite.
- Module-level tool caches outlive a single test, so `real-world.test.ts` calls `clearFinancialsCache`, `clearNewsCache`, `clearOptionsCache`, `clearHoldersCache` in `beforeEach`; without it a case's result depends on which test ran first.
- Tool output wrappers differ by layer and both are asserted as they are: over the wire the server wraps a handler result as `content[0].text` holding JSON; in-process `getEarnings`, `getAnalysis` and `getHistoricalPrices` return the plain object, so there is nothing to `JSON.parse` and no `content` array. `HistoricalTools` is `new HistoricalTools(client, qualityReporter)` with `getHistoricalPrices(args)`; the old `new HistoricalTools(server, client, reporter)` + `handleGetHistoricalPrices` call has not existed since the 2026-10-13 split.
- Resource failures are JSON-RPC errors (they rethrow), tool failures are `isError: true` results; tests assert each per `src/AGENTS.md` and never mix them. `resources/read` payloads are `{ price, meta }` for quote, `{ assetProfile }` for profile, `{ incomeStatementHistory }` for financials, `{ count, news }` for news and `{ earningsTrend, industryTrend, analystOpinion, recommendationTrend }` for analysis.
- Defects these suites pin by name rather than hide: `get_quote_summary` parses and validates nothing, so `{}` performs a live lookup instead of failing on its declared required `symbol`; the registry advertises `count`/`requireRelated` for `get_news`, `period` for the three statement tools and `strikeFilter` for `get_options`, but the handlers read `limit`/`requireRelatedTickers`/`frequency` and no strike filter at all, so the advertised names are stripped and inert; `FinancialsToolCache` keys by symbol/type/frequency only, so a cached page ignores a smaller `limit`; `convert*ToStatementData` hardcodes `period: 'annual'`, so a directly requested quarterly page is mislabelled; `QuoteTools.getQuoteSummary` can never satisfy its own default module list because its only source is `getSummaryProfile`, which asks for `assetProfile`, hence completeness 0; `AnalysisTools.extractTargetPrice` copies the mean into high/low/median; `news.ts` `publishDate` multiplies an epoch that is already milliseconds by 1000 (years around +57000); `tools/list` advertises `maxItems: 100` for `get_quote.symbols` while `InputValidator` caps at 50; `prompts/get` does not enforce the `required: true` flags it advertises and renders missing arguments as the literal `undefined`; the advertised `ticker://{symbol}/historical` template is unreadable — `resources/read` calls `getHistoricalPrices(symbol)` with no options, which requests a full-history daily chart and answers `-32603` with the cause collapsed to `Unknown error`, while the same data via `get_historical_prices` with a bounded `startDate` succeeds.

## Work Guidance

- Keep the per-file harness (`SpawnedServer`, `StdoutFraming`, id-correlated `request`) identical across the four spawned files until someone moves it into `tests/fixtures/`; a fifth copy in `tests/chaos/` follows the same shape.
- If a new case needs a Yahoo response, it goes in that file's live-data `describe`, with a per-test timeout (`test(name, fn, ms)`) rather than a raised global `testTimeout`, and it must assert payload content, not merely that a response arrived.
- Do not add a mock switch, env backdoor, or `USE_MOCK_API`-style fiction to make a live case pass; stub the `yahooFinance` singleton as `real-world.test.ts` does, in-process.
- Fixture imports keep the `.ts` suffix style required by `tests/AGENTS.md`; live symbol/limit values come from `tests/fixtures/test-data.ts` (`validSymbols`, `cryptoSymbols`, `forexPairs`, `quoteFields`, `optionExpirationDates`, `testPeriods`, `newsCounts`, `testLimits`).

## Verification

- `npm run build` then `npx jest tests/e2e` — measured 2026-10-14: 5 suites / 176 tests, 121 of them in the no-network default run and 55 in the live groups. Four consecutive full runs gave 175/176, 176/176, 175/176, 176/176; the only failure was `get_news returns articles with publishers and links` (live group) when Yahoo handed back an empty article list under the parallel load of five children. No offline test varied between runs.
- Offline-only loop: `npx jest tests/e2e/prompt-execution.e2e.test.ts` (26 tests, no network) and `npx jest tests/e2e/real-world.test.ts` (43 tests, stubbed seam, no build required).
- Single file: `npx jest tests/e2e/tool-execution.e2e.test.ts`
- `npm run test:coverage` does not count these toward `src/` coverage gates in any special way; the gate is global.
